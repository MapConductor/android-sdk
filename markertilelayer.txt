MarkerTileLayer Design and Coordination Notes
============================================

Current Policy
--------------
- The `GoogleMapMarkerController` maintains the canonical marker state (position, zoom-indexed scale, cache version, candidates/drawn sets).
- It also participates in tile generation through Google Play Services `TileOverlay`/`TileProvider`, so any tile-related logic there is co-located with the state that influences it.
- For now this controller handles both decisions about which icons to render and preparing the rasterized tiles for Google Maps.

Implications
------------
- Placing tile generation inside the controller keeps state and rendering tightly synchronized, which helps avoid race conditions between zoom updates and tile requests.
- Moving logic elsewhere (e.g. into `core`) would require careful synchronization between controller state and the new tile manager, risking inconsistent zoom-scale snapshots.
- We still want to keep the `core` as the authoritative source for marker metadata (bitmaps, icon metadata, etc.) while controllers consume that data to serve map-specific tile layers.

Migration Considerations
------------------------
- To make MarkerTileLayer re-usable across SDKs, gradually extract the tile-creation orchestration into a `core`-level helper once the controller-based workflow is stable.
- During the transition, maintain the controller’s snapshotting (indexedZoom, bitmapPxToWorldPx, cacheVersion) to avoid mixing generations mid-render.
- Once the `core` helper exists, controllers can delegate tile requests to it while still owning any map-specific hooks (e.g., bridging to Google Maps `TileOverlay`).

Next Steps After Token Recovery
-------------------------------
1. Revalidate the current logging patch and ensure epoch/scale snapshots capture both request-time and current values.
2. Outline the `core` tile manager interface that would accept snapshot data and emit raster tiles for any SDK.
3. When ready, revisit refactoring the controller to call into that interface while keeping the state updates atomic.
