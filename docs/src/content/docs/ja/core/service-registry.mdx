MapConductor には、軽量な「プラグイン」機構として `MapServiceRegistry` があります。
地図SDKモジュール（Google Maps / Mapbox / MapLibre など）と、機能モジュール（クラスタリング / マーカー戦略など）を **継承に頼らずに** 連携させるための仕組みです。

## 仕組み（Android）

- レジストリの持ち主は地図の状態オブジェクトです（`MapViewState.serviceRegistry`）
- `MapViewBase` が CompositionLocal の `LocalMapServiceRegistry` で公開します
- 機能モジュール側はレジストリから capability を解決して利用します

つまり、地図SDKモジュールが capability を「登録」し、機能モジュールがそれを「利用」することで分離を保ちます。

持ち主が状態オブジェクトなのは Android / iOS / React で共通です（いずれも
`MapViewState.serviceRegistry`）。地図インスタンスと寿命が一致し、かつ provider からも
Compose の外のホスト（React Native / Cordova）からも名指しできる唯一のオブジェクトだからです。

## MarkerRenderingSupport

クラスタリングや strategy ベースのレンダリングは、地図SDKごとの renderer/controller が必要です。
それを `MarkerRenderingSupport<ActualMarker>` と `MarkerRenderingSupportKey` で表現します。

組み込みの地図SDKモジュールは `MarkerRenderingSupportKey` を自動登録するため、`mapconductor-marker-clustering` はコントローラの継承なしで動きます。

## 独自地図SDKモジュールでの連携（Android）

独自の地図SDKモジュールを実装する場合は、`state.serviceRegistry` に `MarkerRenderingSupport` を
登録してください。`MapViewBase` は状態オブジェクトから読むので、渡す引数はありません。
`remember { MutableMapServiceRegistry() }` でレジストリを自作しないでください。

```kotlin
// 登録は content の合成より前（コントローラ生成時）に済ませる。
// MarkerClusterGroup は未登録ならその場で return し、レジストリは Compose の state ではないので
// 後から入れても再合成が走らない。
state.serviceRegistry.put(MarkerRenderingSupportKey, myMarkerRenderingSupport)

MapViewBase(
  state = state,
  /* ... */
)
```

状態オブジェクトは composable より長生きするので、ビューが消えるときに登録を取り下げます。
`MarkerRenderingSupportKey` については `MapViewBase` が行います。

```kotlin
DisposableEffect(state) {
  onDispose { state.serviceRegistry.remove(MarkerRenderingSupportKey) }
}
```

`clear()` ではなく `remove()` を使うのは、同じ地図に登録された他の capability を巻き添えに
しないためです。

React Native / Cordova のような非 Compose ホストは状態オブジェクトを持たないため、
`create*ViewController(serviceRegistry = …)` にレジストリを直接渡す形のままです。

## iOS / SwiftUI 補足

iOS にも同じレジストリがあります（`MapServiceKey` / `MapServiceRegistry` /
`MutableMapServiceRegistry` / `MarkerRenderingSupportKey`）。レジストリの実体は状態オブジェクトが持ち、
`MapViewState.serviceRegistry` から参照します（Android と同じです）。provider 側が capability を登録することで、
機能側は provider 非依存のまま拡張できます。

ただし SwiftUI の `Environment` では配りません。地図の中身は `@MapViewContentBuilder` が組み立てる
`MapViewContent` という**値**であって、`MarkerClusterGroup` のようなオーバーレイ項目はビュー階層に
入らないため `@Environment` を読めないからです。Compose と共通なのは「content クロージャが provider の
`body` の**内側**で評価される」点で、provider がその呼び出しを main actor の動的スコープで包むことで
`LocalMapServiceRegistry` と同じ可視範囲になります。

```swift
let mapContent = MapServiceRegistryScope.with(state.serviceRegistry) { content() }
```

追加モジュールは、自分の content が組み立てられているあいだに `MapServiceRegistryScope.current` を読みます。
